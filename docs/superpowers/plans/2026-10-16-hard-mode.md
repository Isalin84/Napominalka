# Жёсткий режим напоминания о разминке: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Окно напоминания о разминке удерживает фокус и не даёт нажать «Готово», пока не прошло время подхода.

**Architecture:** Решение о том, что именно стоит перед кнопкой, принимает чистый модуль `lib/confirmation.cjs`. Главный процесс спрашивает его при показе окна и при записи подхода, окно только отрисовывает отсчёт. Длительность считается один раз в главном процессе и едет в payload готовым числом. Всё поведение закрыто флагом `hardMode.enabled`, выключенным по умолчанию.

**Tech Stack:** Electron 43.2.0, встроенный `node:test`, самописный `scripts/check-text.mjs`. Новых зависимостей нет.

**Spec:** [docs/superpowers/specs/2026-10-16-hard-mode-design.md](../specs/2026-10-16-hard-mode-design.md)

## Global Constraints

- Новых зависимостей не добавлять.
- `hardMode.enabled` по умолчанию `false`. Обновление без вмешательства в настройки ведёт себя как 0.3.0.
- Старый файл настроек без ветки `hardMode` читается без потерь.
- Жёсткий режим действует только при `payload.type === 'movement'` и непустом `payload.exerciseId`. Вода и свои напоминания не меняются.
- Константы: `HOLD_MIN_SECONDS = 20`, `HOLD_MAX_SECONDS = 300`, `SECONDS_PER_REP = 3`, `TOLERANCE_MS = 1000`, `REFOCUS_DELAY_MS = 400`, `HARD_AUTO_SNOOZE_MS = 900000`, `ESC_HOLD_MS = 3000`, `HINT_DELAY_MS = 5000`.
- Все три аварийных выхода ведут в «отложено», а не в «готово».
- Русский текст интерфейса идёт через `/humanizer-ru`: без длинных тире, без риторических вопросов, без оборота «не просто».
- `npm test` обязан проходить после каждой задачи.

## Review Focus

Пять мест, где спека молчит, а человек пострадает. Тест на каждое добавлен в задачу, которой принадлежит код.

1. **Непарсящийся `createdAt` даёт `NaN` в `elapsedMs`.** Сравнение с `NaN` всегда ложно, кнопка не разблокируется никогда, и окно держит человека до пятнадцатиминутной отсечки. Непригодные данные должны открывать ворота, а не запирать их. Тест в задаче 2.
2. **`holdSeconds` отсутствует в payload при включённом жёстком режиме.** Рассогласование между задачами 2 и 3 даёт `seconds: undefined` и ту же вечную блокировку. `gateFor` обязан вернуть `{ kind: 'none' }`. Тест в задаче 2.
3. **Мусор в `perSet`.** Упражнение заводится руками, туда попадает строка, ноль или отрицательное число. Тест в задаче 1.
4. **Жёсткий режим выключили, пока окно висит.** Окно обязано отпустить фокус сразу, не дожидаясь конца отсчёта. Решается тем, что задача 3 спрашивает `gateFor` каждый раз, а не кеширует флаг. Проверка в задаче 6.
5. **Свойства жёсткого окна утекают в следующее напоминание про воду.** Окно создаётся один раз и переиспользуется. Проверка в задаче 6.

Пункты 4 и 5 живут в коде работы с окнами Electron, автотестов на него в проекте нет и заводить харнесс ради двух проверок несоразмерно. Они закрыты ручной проверкой на собранном приложении.

## Уточнение к спеке

Спека описывает флаг `hardGateActive`, поднимаемый в `showReminder`. План вместо него спрашивает `gateFor(activePopupPayload, state)` каждый раз. Поведение то же, но логика переезжает в функцию, покрытую тестами, и пункт 4 из Review Focus закрывается сам собой: выключенная настройка сразу меняет ответ `gateFor`.

const hardState = { hardMode: { enabled: true, confirmBy: 'timer' } };
const movement = { type: 'movement', exerciseId: 'squats', holdSeconds: 36 };

test('gateFor returns no gate when hard mode is off', () => {
  assert.deepEqual(gateFor(movement, { hardMode: { enabled: false } }), { kind: 'none' });
  assert.deepEqual(gateFor(movement, {}), { kind: 'none' });
});

test('gateFor returns no gate for anything but movement', () => {
  assert.deepEqual(gateFor({ type: 'water' }, hardState), { kind: 'none' });
  assert.deepEqual(gateFor({ type: 'custom', title: 'Проветрить' }, hardState), { kind: 'none' });

  assert.deepEqual(gateFor({ type: 'movement', holdSeconds: 36 }, hardState), { kind: 'none' });
});

test('gateFor returns a timer gate for movement in hard mode', () => {
  assert.deepEqual(gateFor(movement, hardState), { kind: 'timer', seconds: 36 });
});

test('gateFor treats an unknown confirmBy as a timer', () => {
  const state = { hardMode: { enabled: true, confirmBy: 'pulse' } };
  assert.deepEqual(gateFor(movement, state), { kind: 'timer', seconds: 36 });

test('gateFor returns no gate when holdSeconds is unusable', () => {

  assert.deepEqual(gateFor({ ...movement, holdSeconds: 0 }, hardState), { kind: 'none' });
  assert.deepEqual(gateFor({ ...movement, holdSeconds: NaN }, hardState), { kind: 'none' });
});

test('isSatisfied is true when there is no gate', () => {
  assert.equal(isSatisfied({ kind: 'none' }, { elapsedMs: 0 }), true);
});

test('isSatisfied is false before the time is up', () => {
  assert.equal(isSatisfied({ kind: 'timer', seconds: 36 }, { elapsedMs: 30000 }), false);
});

test('isSatisfied allows a second of slack between clocks', () => {
  assert.equal(isSatisfied({ kind: 'timer', seconds: 36 }, { elapsedMs: 35200 }), true);
  assert.equal(isSatisfied({ kind: 'timer', seconds: 36 }, { elapsedMs: 34800 }), false);
});

test('isSatisfied is true once the time is up', () => {
  assert.equal(isSatisfied({ kind: 'timer', seconds: 36 }, { elapsedMs: 40000 }), true);
});

test('isSatisfied opens the gate on unusable elapsed time', () => {
  assert.equal(isSatisfied({ kind: 'timer', seconds: 36 }, { elapsedMs: NaN }), true);
  assert.equal(isSatisfied({ kind: 'timer', seconds: 36 }, {}), true);
});

Вызывать его каждый раз, а не кешировать. Выключенная в главном окне настройка обязана подействовать на висящий попап немедленно.

- [ ] **Шаг 4: Развести показ окна по режимам**

В `sendPayload()` внутри `createPopupWindow()` (строка 297) вместо безусловного `showInactive()`:

- жёсткий: `setAlwaysOnTop(true, 'screen-saver')`, на macOS `app.focus({ steal: true })`, затем `show()`, таймер отсрочки на `HARD_AUTO_SNOOZE_MS`;
- обычный: `setAlwaysOnTop(true, 'floating')`, `showInactive()`, таймер на `POPUP_AUTO_SNOOZE_MS`.

Обе ветки выставляют слой явно. Окно переиспользуется между напоминаниями, и невыставленное свойство утечёт в следующее.

- [ ] **Шаг 5: Добавить возврат фокуса**

Проверку `BrowserWindow.getFocusedWindow()` не опускать: без неё главное окно, открытое из трея, не сможет удержать фокус, и выключить жёсткий режим будет негде.

- [ ] **Шаг 6: Проверять ворота при записи подхода**

В начале `recordCompletion()` (строка 427), до записи в историю:

```js
const gate = gateFor(activePopupPayload, state);

```

Сейчас этот канал из окна никто не дёргает: кнопки закрытия в попапе нет, ветка осталась с прежней вёрстки. Спека числит её среди скрываемых в жёстком режиме по ошибке. Удалять ветку не нужно, а защитить стоит: канал живой, и первая же кнопка закрытия в будущем станет дырой в режиме.
