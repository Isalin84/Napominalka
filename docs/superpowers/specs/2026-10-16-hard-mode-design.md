# Жёсткий режим напоминания о разминке

Дата: 16 октября 2026
Статус: согласовано, к реализации принят только этап 1

## Зачем

Напоминание о разминке легко закрыть не вставая со стула. Кнопка «Готово» нажимается за полсекунды, подход записывается, дневная цель растёт, человек продолжает сидеть. Учёт упражнений из версии 0.3.0 при этом показывает красивые цифры, которым нельзя верить.

Задача в том, чтобы отмахнуться стало дороже, чем размяться.

Два рычага:

1. Окно не отпускает, пока человек не ответил. Переключиться на другое приложение не выходит.
2. Кнопка «Готово» недоступна, пока не прошло столько времени, сколько подход реально занимает.

Оба рычага выключаются одним переключателем в настройках. По умолчанию выключены: обновление не должно менять поведение у тех, кто про эту настройку не просил.

## Область действия

Жёсткий режим включается, когда сошлись три условия:

- `state.hardMode.enabled === true`;
- напоминание относится к разминке (`payload.type === 'movement'`);
- в напоминании есть упражнение (`payload.exerciseId` не пустой).

Вода и свои напоминания не меняются никогда. Разминка без активных упражнений не показывается и сейчас, так что третье условие нужно только для надёжности.

## Состояние

В `createDefaultState()` добавляется ветка:

```js
hardMode: {
  enabled: false,
  confirmBy: 'timer'
}
```

`mergeState()` сливает её так же, как `quietHours`: база, поверх сохранённое. Старый файл настроек без `hardMode` читается без потерь и получает значения по умолчанию.

Поле `confirmBy` заселяется сразу, хотя работающее значение у него пока одно. Так формат файла настроек не придётся менять на этапе 2.

На этапе 1 любое прочитанное значение приводится к `'timer'`. Интерфейса, который поставил бы сюда `'pulse'`, ещё нет, а если такое значение попадёт в файл руками, оно не должно заблокировать кнопку навсегда. Разбор `'pulse'` появится вместе с самим пульсом.

## Длительность удержания

Чистая функция в `lib/exercises.cjs`:

```js
const HOLD_MIN_SECONDS = 20;
const HOLD_MAX_SECONDS = 300;
const SECONDS_PER_REP = 3;

holdSeconds(exercise) -> number
```

Правила:

- упражнение в секундах: берём `perSet` как есть;
- упражнение в повторах: `perSet * SECONDS_PER_REP`;
- результат зажимается в границы от 20 до 300 секунд;
- отсутствующее или некорректное упражнение даёт `HOLD_MIN_SECONDS`.

Зажим обязателен. Упражнение заводится вручную, `perSet` ограничен сверху только `MAX_AMOUNT` в сто тысяч. Без верхней границы одна опечатка запирает окно на трое суток.

Коэффициент в три секунды на повтор выбран под обычный темп приседаний и отжиманий. Он сознательно занижен: цель в том, чтобы прокликать было нельзя, а не в том, чтобы измерить подход с секундомером.

Считает длительность только главный процесс. Готовое число кладётся в payload. Попап его показывает, но не вычисляет: иначе один и тот же расчёт жил бы в CommonJS-модуле для главного процесса и в ESM-копии для окна, и они разошлись бы при первой же правке.

## Модуль подтверждения

Новый файл `lib/confirmation.cjs`. Он знает, какое препятствие стоит перед кнопкой «Готово» и преодолено ли оно. Про окна, таймеры и интерфейс он не знает ничего.

```js
gateFor(payload, state) -> Gate
isSatisfied(gate, signal) -> boolean
```

Типы:

```js
Gate =
  | { kind: 'none' }
  | { kind: 'timer', seconds: number }

Signal = { elapsedMs: number }
```

`gateFor` возвращает `{ kind: 'none' }`, если жёсткий режим выключен, напоминание не про разминку или в нём нет упражнения. Иначе `{ kind: 'timer', seconds: payload.holdSeconds }`.

`isSatisfied` для `none` всегда истина. Для `timer` сравнивает `signal.elapsedMs` с `gate.seconds * 1000` минус допуск.

Допуск `TOLERANCE_MS = 1000`. Отсчёт в окне и проверка в главном процессе идут по разным часам, и рендерер может сообщить о готовности на доли секунды раньше. Секунда разницы никого не обманет, а отказ записать честно сделанный подход раздражает.

Этап 2 добавляет сюда третий вид `Gate` и поле `bpm` в `Signal`. Окно, настройки и запись в историю при этом не трогаются.

## Поведение окна

Окно попапа создаётся один раз и переиспользуется между напоминаниями. Поэтому каждый показ обязан выставлять все свойства явно, включая возврат к обычным значениям. Свойство, выставленное в жёстком режиме и не сброшенное потом, утечёт в следующее напоминание про воду.

| Свойство | Обычный показ | Жёсткий |
| --- | --- | --- |
| Появление | `showInactive()` | `show()`, на macOS перед этим `app.focus({ steal: true })` |
| Слой | `setAlwaysOnTop(true, 'floating')` | `setAlwaysOnTop(true, 'screen-saver')` |
| Потеря фокуса | не обрабатывается | вернуть через `REFOCUS_DELAY_MS` |
| Кнопка «Готово» | доступна сразу | заблокирована до конца отсчёта |
| Шестерёнка настроек | показана | скрыта |
| Кнопка закрытия | показана | скрыта |
| Автоматическая отсрочка | `POPUP_AUTO_SNOOZE_MS`, 5 минут | `HARD_AUTO_SNOOZE_MS`, 15 минут |

Константы: `REFOCUS_DELAY_MS = 400`, `HARD_AUTO_SNOOZE_MS = 15 * 60 * 1000`.

Слой `screen-saver` поднимает окно над Dock и строкой меню. Это заметно, но не отнимает у человека управление машиной: Cmd+Tab на macOS перехватить программно нельзя, и мы не пытаемся.

### Возврат фокуса

```js
popupWindow.on('blur', () => {
  if (!hardGateActive) return;
  setTimeout(() => {
    if (!hardGateActive) return;
    if (!popupWindow || popupWindow.isDestroyed() || !popupWindow.isVisible()) return;
    if (BrowserWindow.getFocusedWindow()) return;
    if (process.platform === 'darwin') app.focus({ steal: true });
    popupWindow.focus();
  }, REFOCUS_DELAY_MS);
});
```

Проверка `BrowserWindow.getFocusedWindow()` существенна. Если фокус забрало наше же главное окно, отнимать его обратно нельзя: иначе человек, открывший настройки через трей, не сможет выключить жёсткий режим. Так главное окно становится ещё одним путём наружу.

Флаг `hardGateActive` поднимается в `showReminder` вместе с `activePopupPayload` и опускается в `closePopup`. Привязка к флагу, а не к состоянию настроек, важна: человек может выключить жёсткий режим в главном окне, пока попап висит, и попап обязан отпустить сразу.

### Аварийные выходы

Окно, отбирающее фокус, обязано иметь способ его отдать. Выходов три, по нарастанию усилий.

1. **Удержать Esc три секунды** (`ESC_HOLD_MS = 3000`). Основной путь. Работает надёжно именно потому, что фокус наш и клавиатура приходит в окно. Обработчик в рендерере игнорирует автоповтор (`event.repeat`) и отменяет отсчёт на `keyup` и на `blur`.
2. **Пятнадцать минут.** Окно отпускает себя само. Страховка на случай, если отсчёт сломается.
3. **Выход через трей.** Пункт «Выход» работает всегда и ни от чего в попапе не зависит.

Все три ведут в «отложено», а не в «готово». Пересидеть окно можно, но подход за это не засчитывается и напоминание возвращается через обычный интервал отсрочки. Это сознательно: единственный способ закрыть напоминание насовсем остаётся один, и он требует встать.

## Интерфейс попапа

Payload получает два новых поля: `hardMode: boolean` и `holdSeconds: number`.

Заполняются они только для разминки с упражнением. Для воды и своих напоминаний `hardMode` равен `false`, а `holdSeconds` отсутствует: попап тогда работает по прежней ветке и отсчёта не показывает.

Пока отсчёт идёт:

- кнопка подтверждения заблокирована и подписана отсчётом: `Готово через 0:36`;
- поле количества доступно, человек может поправить число заранее;
- через `HINT_DELAY_MS = 5000` под кнопкой появляется подсказка мелким шрифтом: `Esc удерживать, чтобы отложить`.

Подсказка появляется с задержкой намеренно. Показанный сразу способ обхода читается как предложение им воспользоваться.

Когда отсчёт закончился, кнопка разблокируется и возвращает обычную подпись. Дальше всё как сейчас: прыжок питомца, запись подхода, окно закрывается.

Отсчёт ведётся от `payload.createdAt`, а не от момента отрисовки. Если окно по какой-то причине перерисуется, человек не начнёт ждать заново.

Склонение секунд в подписях берётся из `pluralize` в `petRenderer.js`, как и везде в приложении.

## Проверка в главном процессе

Обработчик `popup:complete` перед записью подхода проверяет:

```js
const gate = gateFor(activePopupPayload, state);
const elapsedMs = Date.now() - new Date(activePopupPayload.createdAt).getTime();
if (!isSatisfied(gate, { elapsedMs })) return;
```

Это не недоверие к своему же окну. Зависший или сбитый таймер в рендерере не должен приводить к записи подхода, которого не было. Проверка стоит две строки и закрывает весь класс таких случаев.

## Задел под пульс

Этап 2 проверяет, что человек действительно дал нагрузку: кнопка «Готово» разблокируется, когда пульс поднялся относительно исходного.

### Что выяснено и пересмотру не подлежит

- **HealthKit на macOS не работает.** Фреймворк в SDK есть с macOS 13, но `isHealthDataAvailable()` возвращает false и доступа к данным нет. [Документация](https://developer.apple.com/documentation/healthkit/hkhealthstore/ishealthdataavailable())
- **Путь через iPhone закрыт.** Синхронизация Watch в Health на телефоне занимает от восьми до двадцати минут и больше, ускорить её API не позволяет. Это касается и Shortcuts, и `HKObserverQuery` с фоновой доставкой. Рост пульса за полторы минуты так не увидеть. [Ответ поддержки разработчиков Apple](https://developer.apple.com/forums/thread/774953)
- **Плотный пульс идёт только в активной тренировке.** В покое часы пишут примерно один замер в пять минут, в `HKWorkoutSession` замер раз в несколько секунд. [Документация](https://developer.apple.com/documentation/healthkit/running-workout-sessions)
- **На watchOS запрещена низкоуровневая сеть.** Сокеты, `NWConnection`, `NWBrowser` и Bonjour недоступны обычным приложениям. Остаётся `URLSession`, то есть обычный HTTP. Следствие: автоматически найти Мак в сети часы не смогут, адрес вводится руками. [TN3135](https://developer.apple.com/documentation/technotes/tn3135-low-level-networking-on-watchos)
- **Часы не вещают стандартный BLE-пульсометр.** Реклама GATT-сервисов на watchOS запрещена. [Документация](https://developer.apple.com/documentation/corebluetooth/cbperipheralmanager)

### Выбранный путь

Готовое приложение на часах [Health Data Server](https://apps.apple.com/us/app/health-data-server/id1496042074), 4,99 доллара. Оно шлёт пульс на заданный адрес и порт, причём с часами общается по обычному REST. Значит, Напоминалка поднимает свой HTTP-порт и принимает данные напрямую, настольная часть разработчика не нужна.

Преимущество перед своим приложением на watchOS: не нужен Xcode, не нужна подпись с пересборкой раз в семь дней на бесплатном Apple ID, и возможность появляется у всех пользователей, а не у одного.

Формат тела запроса публично не описан. Выясняется опытом: поднять слушатель, направить на него часы, посмотреть что приехало.

Источник пульса закрывается тем же интерфейсом `lib/confirmation.cjs`, так что своё приложение на часах или нагрудный датчик встанут на то же место.

### Открытый вопрос к этапу 2

Порог «плюс десять ударов» в текущем виде дырявый. Вставание со стула само поднимает пульс на десять-двадцать ударов, то есть порог берётся сменой позы. Вдобавок пульс отстаёт: после двенадцати приседаний он дорастает до пика секунд через двадцать после последнего повтора.

Правило нужно пересмотреть до реализации. Направление: считать исходное значение по медиане за минуту до напоминания, поднять порог, и требовать, чтобы превышение держалось несколько секунд подряд, а не мелькнуло в одном замере.

## Откат

Всё новое поведение закрыто флагом `hardMode.enabled`, который по умолчанию выключен. Обновление без изменения настроек ведёт себя как 0.3.0.

Работа идёт отдельными коммитами по разделам, порядок отката обычный, как описано в `ROLLBACK.md`. Старый файл настроек читается новой версией без потерь, новый файл старой версией тоже: лишнюю ветку `hardMode` она проигнорирует.
