# Дашборд статистики упражнений

Дата: 16 октября 2026 года.

## Зачем

Приложение записывает каждый подход с 21 сентября, но показать умеет только сегодняшний день. На экране «Упражнения» видно прогресс к дневной цели, в «Истории» — список последних отметок. Ответить на вопрос «я вообще двигаюсь вперёд или топчусь» нечем.

В файле уже лежат 95 подходов за 20 дней из 26, по шести упражнениям. Данные есть, экрана для них нет.

Дашборд отвечает на три вопроса сразу, все три равноценны:

- держусь ли я привычки — регулярность и серии;
- растут ли нагрузки — объём по дням и направление по каждому упражнению;
- реалистичны ли цели — доля целей, доведённых до конца.

## Область действия

| Входит | Не входит |
| --- | --- |
| Упражнения из `exerciseLog` | Вода и свои напоминания |
| Новая вкладка и два новых модуля рендерера | Любые изменения `main.cjs` |
| Чтение состояния | Запись состояния |
| Четыре периода и раскрытие плитки | Экспорт, печать, сравнение с другими людьми |

Главный процесс не трогается вообще. Формат файла настроек не меняется, миграция не нужна, новых зависимостей ноль. Это целиком экранная работа, и откат сводится к `git revert`.

## Где живёт

Новая вкладка «Статистика» в левом меню, между «Упражнениями» и «Историей». Разметка навигации обобщённая: кнопка с `data-view="stats"` и секция с `data-view-panel="stats"` подхватываются существующим `setView` без правок в нём.

Нужна одна новая иконка `chart` в наборе `src/petRenderer.js` — графика там сейчас нет.

Границы периодов:

| Период | От | До | Предыдущий | Шаг графика |
| --- | --- | --- | --- | --- |
| `day` | сегодня 00:00 | сегодня 23:59:59.999 | вчера | `hour` |
| `week` | понедельник этой недели | конец сегодняшнего дня | столько же дней прошлой недели, начиная с её понедельника | `day` |
| `month` | первое число этого месяца | конец сегодняшнего дня | столько же дней прошлого месяца, начиная с первого числа | `day` |

Неделя календарная и начинается с понедельника — так же, как подписи дней в расписании напоминаний. При пустом логе `all` даёт диапазон из одного сегодняшнего дня.

### Предыдущий период обрезается по длине текущего

Текущая неделя в среду длится три дня, а прошлая длилась семь. Сравнивать их напрямую нельзя: до пятницы любая неделя выглядела бы проваленной, и дельта показывала бы минус при совершенно нормальном темпе.

Поэтому предыдущий период берётся не целиком, а ровно той же длины, что уже прошла в текущем: в среду это понедельник, вторник и среда прошлой недели. То же для месяца — шестнадцатого числа сравниваются первые шестнадцать дней обоих месяцев.

Если в прошлом месяце столько дней не было (тридцать первое марта против февраля), предыдущий период кончается последним днём того месяца.

```js
export function bucketSets(log, range)
// → [{ key, label, sets }], по одному элементу на шаг, включая пустые.
```

Шаг берётся из `range.grain`. Для `hour` — 24 элемента, `key` это число часа, `label` — «9». Для `day` — `key` это `'YYYY-MM-DD'`, `label` — число месяца. Для `week` — `key` это дата понедельника, `label` — «12.10».

Пустые шаги присутствуют в массиве. Пропуск должен быть виден как провал, а не исчезнуть из оси.

```js
export function summarize(log, exercises, range, now)
// → { sets, activeDays, totalDays, streak, goalsHit, goalsPossible, deltaSets }
```

- `sets` — число записей в периоде.
- `activeDays` — сколько разных дней в периоде имеют хотя бы одну запись.
- `totalDays` — дней в периоде, не считая будущих. Для текущей недели в среду это 3, а не 7.
- `streak` — текущая серия, см. ниже. Считается от `now`, а не от границ периода: серия не принадлежит периоду.
- `goalsHit` и `goalsPossible` — см. «Доля закрытых целей».
- `deltaSets` — `sets` текущего периода минус `sets` предыдущего, либо `null`, если предыдущего нет.

```js
export function streakDays(log, now)
// → число дней подряд с записями.
```

Серия отсчитывается назад от сегодня. Если сегодня записей ещё нет, счёт начинается со вчера: день не кончился, и обнулять серию до полуночи нечестно. Если нет ни сегодня, ни вчера — ноль.

```js
export function byExercise(log, exercises, range)
// → [{ id, name, unit, target, total, sets, spark, deltaPercent, goalDays, activeDays }]
```

Попадают упражнения, которые включены либо имеют хотя бы одну запись за период. Выключенное упражнение с историей остаётся на экране: история никуда не делась, и прятать её нельзя.

Сортировка по `total` по убыванию.

`name`, `unit` и `target` берутся из списка упражнений, а не из записи лога. В записях лежит имя на момент записи, и после переименования одно упражнение раздвоилось бы на две плитки.

`spark` — массив чисел, выровненный по индексам с результатом `bucketSets` для того же диапазона. Это сумма `amount` по каждому шагу. Один и тот же массив кормит и спарклайн в плитке, и крупный график при раскрытии; подписи оси берутся из `bucketSets`.

`deltaPercent` — рост в процентах к предыдущему периоду, округлённый до целого. `null`, если предыдущего периода нет или в нём было ноль: делить на ноль нельзя, а «рост на бесконечность процентов» не информация.

`goalDays` — сколько дней периода дали по этому упражнению сумму не меньше `target`.

```js
export function calendarWeeks(log, now, weeks = 5)
// → [[{ key, sets, inFuture }]], недели сверху вниз, дни слева направо с понедельника.
```

Последняя неделя содержит сегодня. Дни после сегодня помечены `inFuture` и рисуются пунктирной рамкой без заливки.

## Доля закрытых целей

Знаменатель выбран осознанно, потому что от него зависит, обманывает цифра или нет.

Считаются пары «день и упражнение», по которым в этот день была хотя бы одна запись. `goalsPossible` — число таких пар. `goalsHit` — сколько из них дали сумму не меньше `target`.

То есть цифра отвечает на вопрос «за что брались, то довели?», а не «сколько из всех возможных целей закрыли». Второй знаменатель дал бы для месяца с шестью упражнениями 186 пар и цифру около десяти процентов, которая верна арифметически и бесполезна практически.

Упражнения с `target` меньше единицы или без него выбрасываются из обеих частей дроби. Это же закрывает деление на ноль.

Подпись на экране называет знаменатель прямо, чтобы цифру нельзя было прочитать не так: «из упражнений, за которые брались».

## Единица главного графика

Главный график считает **подходы**, а не повторения.

Повторения складывать нельзя. Двенадцать приседаний и двенадцать подтягиваний — не двадцать четыре одинаковых повторения, и день с лёгкими упражнениями выглядел бы продуктивнее дня с тяжёлыми. Вдобавок приложение разрешает упражнения в секундах, а секунды с повторениями не складываются вообще.

Подход — то, как приложение на самом деле записывает работу, и он сравним всегда.

Внутри плитки вопроса нет: там одно упражнение, его повторения сравнимы сами с собой, и подпись идёт в его собственных единицах — «раз» или «сек.».

## Экран

Сверху вниз.

**1. Шапка.** Надзаголовок «УПРАЖНЕНИЯ», заголовок «Статистика», справа переключатель из четырёх кнопок: День, Неделя, Месяц, Всё время.

**2. Четыре метрики** в ряд, карточками:

| Метрика | Значение | Подпись снизу |
| --- | --- | --- |
| Подходов | `sets` | дельта к прошлому периоду, либо пусто |
| Дней с занятиями | `activeDays` из `totalDays` | — |
| Подряд | `streak` в днях | — |
| Цели закрыты | `goalsHit` из `goalsPossible` | «из упражнений, за которые брались» |

**3. График подходов.** Заголовок меняется по шагу: «Подходы по часам», «Подходы по дням», «Подходы по неделям». Столбики из `bucketSets`. Сегодняшний столбик золотой, остальные тёмно-синие.

Для периода «День» шаг часовой, и график отвечает на вопрос, которого больше нигде нет: в какое время суток вы занимаетесь. Без этого «День» просто повторял бы экран «Упражнения».

**4. Календарь регулярности.** Пять недель, всегда, независимо от выбранного периода: вопрос «держусь ли я» не принадлежит периоду. Заливка по числу подходов за день.

| Подходов за день | Заливка |
| --- | --- |
| 0 | `--mist` |
| 1–2 | светлый синий |
| 3–5 | средний синий |
| 6 и больше | `--navy` |

Сегодняшняя ячейка получает золотую рамку. Будущие дни — пунктирная рамка без заливки.

**5. Плитки упражнений.** Сетка по три в ряд. В плитке: имя, значок направления с процентом, итог за период крупно, спарклайн, подпись «Цель закрыта: 4 из 13 дней».

Направление: зелёный значок при росте, красный при падении, ничего если сравнивать не с чем.

> Поправлено по ходу работ 16 октября 2026 года. Исходно спека требовала значок «новое» при пустом прошлом периоде. На «Месяце» шестнадцатого числа прошлый период — первая половина сентября, где записей нет вовсе, и «новое» загоралось разом у всех упражнений, включая те, которые человек делает месяц. Программа знает «сравнивать не с чем», а говорила «этого раньше не было», поэтому при неизвестной дельте значка теперь нет вовсе.

Клик по плитке разворачивает её на всю ширину сетки и показывает крупный график этого упражнения по шагам периода. Второй клик сворачивает. Раскрыта может быть одна плитка.

Пунктирная линия дневной цели рисуется только при дневном шаге и только тогда входит в масштаб.

> Поправлено по ходу работ 16 октября 2026 года. Исходно спека требовала линию без оговорок про шаг, и это была ошибка. На периоде «День» шаг часовой, на «Всём времени» при длинной истории недельный, и дневная цель сравнивалась бы там с часовыми или недельными суммами. Вдобавок цель входит в масштаб: цель 60 против часовых столбиков по 5 сжала бы их в неразличимые полоски.

## Пустые состояния

| Когда | Что показываем |
| --- | --- |
| Записей нет вообще | Одно сообщение вместо всего экрана: «Здесь появится статистика, когда наберутся первые подходы.» Пустые оси и нули не рисуем |
| В периоде записей нет, но в истории есть | Метрики по нулям, график с подписью «За этот период подходов нет», календарь и плитки как обычно |
| Упражнение без записей за период | Плитка остаётся с нулём и ровной серой линией. Исчезающая плитка заставляла бы сетку прыгать при смене периода |

## Тексты

Все строки проходят через `/humanizer-ru` перед коммитом. Два правила из прошлых разборов действуют и здесь: род пользователя нигде не проявляется (поэтому «Дней с занятиями», а не «Дней занимался»), и слова из кода в интерфейс не попадают.

Числительные склоняются через существующий `pluralize`.

## Проверки

`test/stats.test.mjs`, запускается из `npm test`. Пинуем то, что ломается молча:

| Что проверяем | Почему именно это |
| --- | --- |
| Границы всех четырёх периодов на фиксированном `now` | Сдвиг на день перекрашивает весь экран |
| `week` начинается с понедельника, а не с воскресенья | Сутки расхождения с расписанием напоминаний |
| `totalDays` не считает будущие дни | Иначе текущая неделя всегда выглядит проваленной |
| Предыдущий период обрезан по длине текущего | Полная прошлая неделя против трёх прожитых дней даёт ложный минус |
| Тридцать первое число при коротком прошлом месяце | Предыдущий период кончается последним днём того месяца |
| Серия, когда сегодня пусто, а вчера есть | Серия не должна обнуляться до полуночи |
| Серия с пропуском посередине | Считается только непрерывный хвост |
| Серия при пустом логе | Ноль, а не исключение |
| `goalsPossible` не растёт от упражнений без записей в этот день | Знаменатель определён в спеке именно так |
| `target` равен нулю или отсутствует | Упражнение выпадает из дроби, деления на ноль нет |
| Переименованное упражнение даёт одну плитку | `name` берётся из списка, не из записи |
| `deltaPercent` равен `null`, когда прошлый период пуст | Не «плюс бесконечность» |
| Шаг переключается на недельный после 70 дней | Иначе через год тысяча столбиков |
| Пустые шаги присутствуют в `bucketSets` | Пропуск должен быть виден |
| Запись с `exerciseId`, которого нет в списке | Не падаем, запись игнорируется |
| Упражнение в секундах | `unit` доезжает до плитки без искажений |

Проверка глазами на собранном приложении: переключение всех четырёх периодов, раскрытие и сворачивание плитки, экран при пустом периоде.

## Откат

Одна задача — один коммит. Главный процесс и формат данных не меняются, поэтому откат любого коммита или всего диапазона безопасен: достаточно `git revert`, данные пользователя при этом в принципе не затрагиваются.

## Риски

**Весь лог перечитывается при каждой отрисовке.** При 95 записях это незаметно. Тысяча записей тоже пройдёт без разницы. Проблема начнётся где-то за десятками тысяч, то есть лет через десять такого темпа. Оптимизация сейчас была бы работой на несуществующую беду, но порог записан, чтобы его узнали, когда он придёт.

**Подсказки при наведении надо писать руками.** Готовых библиотек графиков нет и не будет: CSP запрещает внешние скрипты, а зависимостей в проекте ноль. Если столбиков много, число за столбиком читается только наведением, и это отдельная работа внутри `statsView.js`.

**Переход на зимнее время.** `dayKey` работает по локальной дате, поэтому сутки с переводом стрелок будут длиться 23 или 25 часов. На счёт дней и серий это не влияет, на часовой график в один день в году — влияет на один столбик. Чинить не планируем.
